Every State at Once

Experiment № 117 · November 18, 2026

Ken Thompson, 1968: to match a regular expression, compile it into a little machine of states and arrows, then read the text once, keeping track of every state you could be in at the same time. It never guesses, so it never has to go back.

Syntax: letters match themselves, . matches any character, | means or, * + ? repeat what's before them, ( ) groups, and \ makes the next character literal.

Why it's worth knowing: Thompson's method costs at most pattern size × text length, whatever you feed it. Most languages' regex engines backtrack instead, and on patterns like the trap that can take exponential time. That's the ReDoS family of bugs, and a regex like that took down Cloudflare's network in 2019. RE2, Go and Rust use the automaton.

Experiment № 117 · The story

Every State at Once

Why I picked it

I use regular expressions all the time, and for years I assumed they worked by trial and error: try one way of matching, and if it fails, back up and try another. That's how most of the engines I use really do it. Then I read Ken Thompson's four-page paper from 1968, "Regular expression search algorithm", where he does something different. He turns the pattern into a small machine and runs every possible path through it at once. He wrote it for the IBM 7094, and it went on to sit inside the editors and tools that grep came from. This gallery already has string search with Knuth, Morris and Pratt, and parsing with Dijkstra's railway siding, but nothing about the tool I reach for most.

What I enjoy about it

The construction is lovely because every piece of a pattern is a tiny machine with one way in and one way out. A letter is one arrow. Two pieces in a row are joined end to end. An "or" splits into two lanes that meet again. A star adds a loop back over the top and a bypass underneath. You can watch the drawing grow exactly the way the pattern reads.

The run is what I like most. A state the machine might be in is just a lit circle, and reading a character moves every light at once: lights that can't follow the character go out, and lights that can jump forward, then spread along the free ε arrows. The grid underneath keeps a record of it. Then try the trap. A backtracking engine checks the pattern a?a?a?…aaa against a run of a's and has to try almost every combination of taking or skipping each optional a, doubling its work every time n goes up by one. Thompson's machine just lights a few more circles.

Something you might take away

When you have to choose and you don't know which choice is right, you don't always have to pick one and hope. Sometimes you can keep every option alive together, as long as you merge the ones that end up in the same place. Here there are only so many states, so the set of possibilities can never grow larger than the machine, and you only ever need to move forward.
